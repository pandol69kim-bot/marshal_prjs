## 2차 작업 — 빌드 오류 수정 (오류 체크)

### 오류 1: LifecyclePhaseNotFoundException

**증상**: `./mvnw spring-boot:run -Dspring-boot.run.profiles=local` 실행 시 Maven 라이프사이클 오류

**원인**: Windows PowerShell에서 `-D` 파라미터가 분리되어 `local`이 Maven 라이프사이클 phase로 해석됨

**해결**:
```powershell
# PowerShell 올바른 실행 방법
$env:SPRING_PROFILES_ACTIVE="local"
.\mvnw.cmd spring-boot:run
```

---

### 오류 2: 코드 버그 — `AsyncExternalService.java`

**증상**: `onStatus` 핸들러가 4xx를 중복 처리, 5xx 처리 누락

**원인**:
```java
// 수정 전 (버그)
.onStatus(status -> status.is4xxClientError(), ...)
.onStatus(status -> status.is4xxClientError(), ...)  // 중복!

// 수정 후
.onStatus(status -> status.is4xxClientError(), ...)
.onStatus(status -> status.is5xxServerError(), ...)  // 수정
```

**수정 파일**: `infrastructure/external/AsyncExternalService.java`

---

### 오류 3: 환경 변수 미설정으로 인한 기동 실패

**증상**: `APPLICATION FAILED TO START` — `DATABASE_URL`, `JWT_SECRET`, `S3_ACCESS_KEY` 등 필수 환경 변수 없음

**원인**: `application.yml`의 `${DATABASE_URL}`, `${JWT_SECRET}`, `${S3_ACCESS_KEY}`, `${S3_SECRET_KEY}`는 기본값 없음. `spring-boot:run`은 `.env` 파일을 자동으로 읽지 않음.

**해결**: `application-local.yml` 재구성 (Docker Compose 기준 설정값 포함)

| 설정 | 값 |
|------|-----|
| DB URL | `jdbc:postgresql://localhost:5432/appdb` |
| DB User | `postgres` (docker-compose 기준) |
| DB Password | `postgres` |
| JWT Secret | `local-dev-secret-key-min-32-characters-long` |
| S3 Endpoint | `http://localhost:9000` (MinIO) |
| S3 Access Key | `minioadmin` |

> **발견된 부가 오류**: 초기 `application-local.yml`에 `appuser/apppass` 설정 → docker-compose의 `postgres/postgres`와 불일치 → DB 연결 실패. 수정 완료.

### 오류 4 (핵심): `SendGridClient` Bean 생성 실패

**증상**:
```
Error creating bean with name 'sendGridEmailAdapter':
  Error creating bean with name 'SendGridClient':
    FactoryBean threw exception on object creation
```

**원인**: `feign.circuitbreaker.enabled=true` 상태에서 fallback이 없는 Feign 클라이언트는 Bean 생성 실패

| 클라이언트 | fallback | 결과 |
|-----------|---------|------|
| `ExternalDataClient` | `ExternalDataClientFallback` ✓ | 정상 생성 |
| `SendGridClient` | 없음 ✗ | **Bean 생성 실패** |

**해결**:

| 수정 | 파일 |
|------|------|
| `SendGridClientFallback.java` 신규 생성 | `infrastructure/external/fallback/` |
| `SendGridClient`에 `fallback = SendGridClientFallback.class` 추가 | `infrastructure/external/client/` |
| `feign.circuitbreaker.enabled: false` 추가 (로컬 안전망) | `application-local.yml` |

## 3차 작업 — 추가 빌드 오류 수정 (오류 체크)

### 오류 5: `Could not resolve placeholder 'JWT_SECRET'`

**증상**:
```
Caused by: java.lang.IllegalArgumentException:
  Could not resolve placeholder 'JWT_SECRET' in value "${JWT_SECRET}"
```

**원인**: `application-local.yml`이 로드되지 않아 `application.yml`의 `${JWT_SECRET}` 플레이스홀더를 환경 변수에서 직접 찾으려 했으나 미설정

**근본 원인**: Windows PowerShell에서 `$env:SPRING_PROFILES_ACTIVE="local"` 설정 후 `2>&1 | Select-String` 파이프라인 실행 시 환경 변수가 하위 프로세스에 제대로 전달되지 않음

**해결**: `.mvn/jvm.config` 파일 생성

```
-Dspring.profiles.active=local
```

Maven Wrapper(`mvnw.cmd`) 실행 시 이 파일을 자동으로 읽어 JVM 인수로 추가. 별도 환경 변수 설정 없이 `application-local.yml`이 항상 로드됨.

**수정 파일**: `.mvn/jvm.config` (신규 생성)

> **운영 배포 시 주의**: `.mvn/jvm.config`를 삭제하거나 `.gitignore`에 추가하고 실제 환경 변수를 사용해야 합니다.
