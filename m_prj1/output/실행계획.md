## 차단 이슈 (구동 전 필수 수정)

### 이슈 1 — OAuth2 redirect-uri 누락 (CRITICAL)

**파일:** `backend/src/main/resources/application-local.yml`

**오류 메시지:**
```
java.lang.IllegalArgumentException: redirectUri cannot be empty
  at ClientRegistration$Builder.validateAuthorizationCodeGrantType
```

**원인:** Spring Security OAuth2는 authorization_code grant type 사용 시 각 provider별 `redirect-uri`가 필수.
현재 `google`, `kakao` registration 블록에 `redirect-uri` 키가 없음.

**수정 내용:**

```yaml
# 현재 (오류 발생)
spring:
  security:
    oauth2:
      client:
        registration:
          google:
            client-id: dummy-google-client-id
            client-secret: dummy-google-client-secret
          kakao:
            client-id: dummy-kakao-client-id
            client-secret: dummy-kakao-client-secret

# 수정 후
spring:
  security:
    oauth2:
      client:
        registration:
          google:
            client-id: dummy-google-client-id
            client-secret: dummy-google-client-secret
            redirect-uri: http://localhost:8080/login/oauth2/code/google  # ← 추가
          kakao:
            client-id: dummy-kakao-client-id
            client-secret: dummy-kakao-client-secret
            redirect-uri: http://localhost:8080/login/oauth2/code/kakao   # ← 추가
```

## 실행계획 — 로컬 개발 모드 (권장)

> Docker로 인프라만 올리고, 백엔드·프론트엔드는 로컬에서 직접 실행.
> 핫 리로드, 디버깅 용이.

### Step 1. OAuth2 redirect-uri 수정

`backend/src/main/resources/application-local.yml` 에 위 수정 내용 적용.

### Step 2. 인프라 기동 (Docker)

```bash
cd D:\Marchall_CLAUDE\m_prj1\output\project

docker-compose up -d postgres redis minio
```

**헬스체크 확인:**
```bash
docker-compose ps
# postgres: healthy, redis: healthy, minio: running 확인
```

### Step 3. MinIO 버킷 생성

MinIO 최초 기동 시 `uploads` 버킷이 없으면 백엔드 오류 발생 가능.

```bash
# MinIO 콘솔 접속: http://localhost:9001
# ID: minioadmin / PW: minioadmin
# Buckets → Create Bucket → 이름: uploads
```

또는 mc CLI 사용:
```bash
docker run --rm --network host minio/mc:latest \
  alias set local http://localhost:9000 minioadmin minioadmin && \
  mc mb local/uploads --ignore-existing
```

### Step 4. 백엔드 실행

```bash
cd D:\Marchall_CLAUDE\m_prj1\output\project\backend

./mvnw spring-boot:run -Dspring-boot.run.profiles=local
```

**정상 기동 확인 로그:**
```
Started ApiServiceApplication in X.XXX seconds
```

**오류 시 확인 사항:**
- Flyway 마이그레이션 오류 → `flyway.clean-on-validation-error: true` 설정됨, 자동 복구
- DB 연결 실패 → postgres 컨테이너 헬스체크 재확인

### Step 5. 프론트엔드 실행

```bash
cd D:\Marchall_CLAUDE\m_prj1\output\project\frontend

npm install   # node_modules 존재 시 생략 가능
npm run dev
```

## 실행계획 — Docker Compose 전체 (배포/통합 테스트)

> 프론트·백엔드 모두 Docker 이미지로 실행. `.env` 실제 값 필요.

### Step 1. .env 설정

```bash
# D:\Marchall_CLAUDE\m_prj1\output\project\.env
JWT_SECRET=local-dev-secret-key-min-32-characters   # 32자 이상
GOOGLE_CLIENT_ID=실제값_또는_dummy
GOOGLE_CLIENT_SECRET=실제값_또는_dummy
KAKAO_CLIENT_ID=실제값_또는_dummy
KAKAO_CLIENT_SECRET=실제값_또는_dummy
```

> OAuth2 실제 사용하지 않는 경우 `dummy` 값 가능 (단, redirect-uri는 여전히 필요).

### Step 2. 전체 빌드 및 기동

```bash
cd D:\Marchall_CLAUDE\m_prj1\output\project

docker-compose up -d --build
```

빌드 시간: 백엔드 Maven 빌드 약 3~5분, 프론트엔드 npm 빌드 약 1~2분.

### Step 3. 상태 확인

```bash
docker-compose ps
docker-compose logs -f backend   # 백엔드 기동 로그 확인
```

## 특이사항

- `application-local.yml`의 `jwt.secret`은 이미 32자 이상 로컬용 값으로 설정됨 → `.env` JWT_SECRET 없어도 로컬 모드에서는 동작
- 기존 `app-postgres`, `app-backend` 등 중지된 컨테이너는 **별도 프로젝트**의 잔여물 — 포트 충돌 가능성 있음 (`5432`, `8080`)
- 포트 충돌 시: `docker rm app-postgres app-backend app-frontend app-nginx` 후 재시도
- Flyway V1, V2 마이그레이션 파일 존재 — DB 스키마 자동 적용됨
