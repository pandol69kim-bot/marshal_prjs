# 로그인 오류 수정 내용

## 1) 증상
- **Google OAuth2 로그인 시**
  - `400 오류: redirect_uri_mismatch`
- **프론트(Nginx)에서**
  - `502 Bad Gateway (nginx/1.25.5)`

## 2) 원인 정리

### (A) 502 Bad Gateway 원인
- 프론트 컨테이너의 Nginx가 `/oauth2`, `/login`, `/api` 요청을 `http://backend:8080`으로 프록시하도록 설정되어 있음.
- 백엔드(Spring Boot/Tomcat)가 **기동 완료되기 전**에 해당 경로로 요청이 들어오면, Nginx가 upstream에 연결할 수 없어 아래와 같이 502가 발생함.
  - `connect() failed (111: Connection refused) while connecting to upstream`

### (B) OAuth2 시작 요청 실패 원인 (백엔드)
- 백엔드 로그에서 아래 오류가 확인됨.
  - `Map has no value for 'OAUTH2_REDIRECT_URI_GOOGLE'`
- `application.yml`의 `spring.security.oauth2.client.registration.google.redirect-uri` 설정이 환경변수 형태로 잡혀 있었고, 이 값이 런타임에서 정상 해석되지 않으면서 Spring Security가 redirect URI 템플릿 확장 과정에서 예외가 발생함.

## 3) 적용한 수정(코드)

### 수정 파일
- `output/project/backend/src/main/resources/application.yml`

### 수정 내용
- Google/Kakao OAuth2 `redirect-uri`를 Spring Security 권장 템플릿으로 변경
  - `"{baseUrl}/login/oauth2/code/{registrationId}"`

이 변경으로 다음이 보장됨:
- 현재 요청의 호스트/스킴 기반으로 콜백 URL이 자동 생성됨
- 환경변수 누락/해석 문제로 OAuth2 시작 단계가 깨지는 문제를 제거

## 4) 재배포/반영 방법 (Docker 사용 시)
- 단순 `restart`만으로는 컨테이너 이미지 안의 `app.jar`가 바뀌지 않을 수 있으므로, 아래처럼 **재빌드**가 필요함.

```bash
docker compose up -d --build backend
```

## 5) 정상 동작 확인(검증 결과)

### 백엔드 직접 접근
- `http://localhost:8080/oauth2/authorization/google` 호출 시
  - Google 인증 URL로 `302` 리다이렉트가 발생하고, `redirect_uri`가 아래 형태로 생성되는 것을 확인함:
    - `http://localhost:8080/login/oauth2/code/google`

### Nginx(프론트) 경유 접근 (포트 80)
- `http://localhost/oauth2/authorization/google` 호출 시
  - Google 인증 URL로 `302` 리다이렉트가 발생하고, `redirect_uri`가 아래 형태로 생성되는 것을 확인함:
    - `http://localhost/login/oauth2/code/google`

> 참고: Nginx 경유로 로그인 흐름을 탈 경우, Google이 돌아오는 콜백도 `http://localhost/login/oauth2/code/google`가 됩니다.

## 6) Google Cloud Console 설정(필수)
Google Cloud Console → OAuth Client → **Authorized redirect URIs**에, 실제로 사용하는 경로를 **정확히** 등록해야 합니다.

- **Nginx(포트 80) 경유로 사용할 경우**
  - `http://localhost/login/oauth2/code/google`
- **백엔드(8080) 직접으로 사용할 경우**
  - `http://localhost:8080/login/oauth2/code/google`

`redirect_uri_mismatch`는 아래가 1글자라도 다르면 발생합니다:
- `http` vs `https`
- `localhost` vs `127.0.0.1`
- 포트 번호
- 경로
- 슬래시(`/`) 유무

## 7) PowerShell에서 curl 사용 주의
Windows PowerShell에서는 `curl`이 `Invoke-WebRequest` 별칭이라 옵션(`-I`, `-w` 등)이 예상대로 동작하지 않을 수 있습니다.
확인 명령은 `curl.exe`를 사용하세요.

예:
```bash
curl.exe -s -I http://localhost/oauth2/authorization/google
```
