## [2026-04-16] docker-compose.dev.yml 오류 수정

### 메타 정보
- **날짜:** 2026-04-16
- **작업명:** Docker Compose dev 환경 서비스 의존성 오류 수정
- **대상 파일:** `docker-compose.dev.yml`

### 프롬프트 (사용자 요청)
```
오류체크 \project>docker compose -f docker-compose.yml -f docker-compose.dev.yml up
service "frontend" depends on undefined service "backend": invalid compose project
```

### 오류 원인
`docker-compose.dev.yml`에서 `backend` 서비스에 `profiles: [disabled]`를 설정하면,
Docker Compose가 해당 서비스를 **"미정의 서비스(undefined service)"** 로 취급한다.

`frontend` 서비스의 `depends_on: - backend`가 미정의 서비스를 참조하게 되어
프로젝트 로드 시점에 유효성 검사 오류가 발생한다.

### 수정 내용

**수정 전 (`docker-compose.dev.yml`)**
```yaml
services:
  backend:
    profiles:
      - disabled

  frontend:
    ...
    depends_on: []
```

**수정 후 (`docker-compose.dev.yml`)**
```yaml
services:
  backend:
    image: alpine
    command: sh -c "echo 'Backend is running locally on host (not in Docker)' && tail -f /dev/null"
    ports: []
    environment: {}
    depends_on: {}
    healthcheck:
      test: ["CMD", "true"]
      interval: 30s
      timeout: 5s
      retries: 1
    restart: "no"

  frontend:
    ...
    depends_on:
      - backend
```

### 변경 사항 상세

| 항목 | 변경 전 | 변경 후 |
|------|---------|---------|
| `backend` 비활성화 방식 | `profiles: [disabled]` | `alpine` 이미지 no-op 컨테이너 |
| `backend` 포트 | 기본값 유지 | `[]` (포트 없음) |
| `backend` 환경변수 | 기본값 유지 | `{}` (없음) |
| `backend` 재시작 정책 | `unless-stopped` | `"no"` |
| `frontend.depends_on` | `[]` | `- backend` |

### 결과
- 더미 `backend` 컨테이너가 먼저 시작 (8080 포트 없음 → 로컬 실행 백엔드와 충돌 없음)
- `frontend` Vite dev server가 이후 정상 시작
- `docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d` 오류 해결

### 특이사항
- `profiles: [disabled]`는 Docker Compose 공식 "비활성화" 기능이 아님
  - 해당 프로필이 활성화되지 않으면 서비스가 "미정의"로 처리되어 의존성 오류 발생
- no-op `alpine` 컨테이너는 로컬에서 직접 실행되는 실제 백엔드(`localhost:8080`)와 독립적으로 동작

## [2026-04-16] Vite `@` 별칭 미해석 오류 수정

### 메타 정보
- **날짜:** 2026-04-16
- **작업명:** Docker 컨테이너 내 Vite 설정 파일 누락으로 인한 모듈 해석 실패 수정
- **대상 파일:** `docker-compose.dev.yml`

### 프롬프트 (사용자 요청)
```
오류체크
frontend-1  | Error: The following dependencies are imported but could not be resolved:
frontend-1  |   @/components/ui/BaseToast.vue (imported by /app/src/App.vue?id=0)
frontend-1  |   @/stores/auth.store (imported by /app/src/router/index.ts)
frontend-1  |   @/pages/LoginPage.vue (imported by /app/src/router/index.ts)
frontend-1  |   ... (이하 동일)
```

### 오류 원인
`Dockerfile.dev`는 `package*.json`만 컨테이너에 복사하고,
`docker-compose.dev.yml` 볼륨 마운트에 **`vite.config.ts`가 포함되지 않았다.**

Vite는 `@` → `/app/src` 별칭 매핑을 `vite.config.ts`의 `resolve.alias`에서 읽는다.
컨테이너 안에 이 파일이 없으므로 `@/...` 경로를 해석하지 못해 모든 컴포넌트를 찾을 수 없게 된다.

```
# 컨테이너 내부 실제 상태 (수정 전)
/app/
├── package.json       ← COPY됨
├── node_modules/      ← npm install됨
├── src/               ← volume mount됨
│   └── ...
│
# 없음: vite.config.ts, tsconfig*.json
```

### 수정 내용

**수정 전 (`docker-compose.dev.yml` volumes)**
```yaml
volumes:
  - ./frontend/src:/app/src
  - ./frontend/public:/app/public
  - ./frontend/index.html:/app/index.html
  - /app/node_modules
```

**수정 후 (`docker-compose.dev.yml` volumes)**
```yaml
volumes:
  - ./frontend/src:/app/src
  - ./frontend/public:/app/public
  - ./frontend/index.html:/app/index.html
  - ./frontend/vite.config.ts:/app/vite.config.ts        # @ 별칭 해석에 필수
  - ./frontend/tsconfig.json:/app/tsconfig.json
  - ./frontend/tsconfig.app.json:/app/tsconfig.app.json
  - ./frontend/tsconfig.node.json:/app/tsconfig.node.json
  - /app/node_modules
```

### 변경 사항 상세

| 추가된 마운트 | 용도 |
|-------------|------|
| `vite.config.ts` | `@` 별칭 정의 (`resolve.alias`) — **핵심** |
| `tsconfig.json` | TypeScript 기본 설정 |
| `tsconfig.app.json` | 앱 소스 TypeScript 설정 |
| `tsconfig.node.json` | Vite 설정 파일용 TypeScript 설정 |

### 결과
- `@/components/...`, `@/stores/...`, `@/pages/...` 등 모든 `@` 경로 정상 해석
- Vite dev server 정상 기동

### 특이사항
- 볼륨 마운트 방식으로 추가했으므로 로컬에서 `vite.config.ts` 수정 시 컨테이너 재빌드 없이 반영됨
- 컨테이너 재시작이 필요한 경우: `docker compose ... restart frontend`

## [2026-04-16] Tailwind CSS 미적용 오류 수정

### 메타 정보
- **날짜:** 2026-04-16
- **작업명:** Docker 컨테이너 내 Tailwind/PostCSS 설정 파일 누락으로 인한 CSS 미적용 수정
- **대상 파일:** `docker-compose.dev.yml`

### 프롬프트 (사용자 요청)
```
http://localhost:5173/login  css 적용이 안되고 있는데 확인해줘.
```

### 오류 원인
`docker-compose.dev.yml` 볼륨 마운트에 **`tailwind.config.js`와 `postcss.config.js`가 없었다.**

Vite는 CSS 처리 시 PostCSS를 통해 `@tailwind base/components/utilities` 디렉티브를 실제 CSS로 변환한다.
이 변환은 `postcss.config.js`가 있어야 작동하며, `tailwind.config.js`가 없으면 `content` 경로를 찾지 못해 클래스를 생성하지 못한다.

```
# CSS 처리 흐름
main.css (@tailwind 디렉티브)
  → PostCSS (postcss.config.js 필요)
    → Tailwind CSS 플러그인 (tailwind.config.js 필요)
      → 실제 CSS 클래스 생성
```

컨테이너에 두 파일이 없으면 `@tailwind` 디렉티브가 빈 CSS로 처리되어 스타일이 전혀 적용되지 않는다.

### 수정 내용

**수정 전 (`docker-compose.dev.yml` volumes)**
```yaml
volumes:
  - ./frontend/src:/app/src
  - ./frontend/vite.config.ts:/app/vite.config.ts
  - ./frontend/tsconfig.json:/app/tsconfig.json
  ...
```

**수정 후 (`docker-compose.dev.yml` volumes)**
```yaml
volumes:
  - ./frontend/src:/app/src
  - ./frontend/vite.config.ts:/app/vite.config.ts
  - ./frontend/tailwind.config.js:/app/tailwind.config.js  # 추가
  - ./frontend/postcss.config.js:/app/postcss.config.js    # 추가
  - ./frontend/tsconfig.json:/app/tsconfig.json
  ...
```

### 변경 사항 상세

| 추가된 마운트 | 용도 |
|-------------|------|
| `tailwind.config.js` | content 경로, theme(primary 색상 등) 정의 — Tailwind 클래스 생성에 필수 |
| `postcss.config.js` | `@tailwind` 디렉티브를 실제 CSS로 변환하는 PostCSS 파이프라인 설정 |

### 결과
- `@tailwind base/components/utilities` 정상 처리
- `bg-gray-50`, `text-gray-900`, `rounded-xl`, `card` 등 모든 Tailwind 클래스 적용
- `/login` 페이지 스타일 정상 렌더링

### 적용 방법
```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build frontend -d
```

## [2026-04-16] Spring Boot 기동 실패 — `jwt.*` 속성 미해석 수정

### 메타 정보
- **날짜:** 2026-04-16
- **작업명:** `application.yml` 누락으로 인한 Spring Boot 속성 플레이스홀더 해석 실패 수정
- **대상 파일:** `backend/src/main/resources/application.yml` (신규 생성)

### 프롬프트 (사용자 요청)
```
Caused by: java.lang.IllegalArgumentException:
  Could not resolve placeholder 'jwt.access-token-expiry' in value "${jwt.access-token-expiry}"
```

### 오류 원인
`application.yml`이 git에서 삭제된 상태였다 (커밋 `bd171c1`).

Spring Boot 기동 흐름:
1. 기본 `application.yml` 로드 → **파일 없음**
2. `application-local.yml` 로드 → 프로필이 활성화되지 않으면 로드 안 됨
3. `JwtProvider`가 `${jwt.access-token-expiry}` 주입 시도 → 속성 없음 → **IllegalArgumentException**

`jwt.*` 속성은 `application-local.yml`에만 정의되어 있었으나,
`local` 프로필이 활성화되지 않으면 해당 파일 자체가 로드되지 않는다.

### 수정 내용

**신규 생성: `application.yml`**
- 모든 `@Value` 속성을 환경변수 참조로 정의
- 비밀이 아닌 값에는 `:default` 기본값 제공
- `JWT_SECRET`처럼 필수 시크릿은 기본값 없이 환경변수 강제

```yaml
jwt:
  secret: ${JWT_SECRET}                          # 환경변수 필수
  access-token-expiry: ${JWT_ACCESS_TOKEN_EXPIRY:900}
  refresh-token-expiry: ${JWT_REFRESH_TOKEN_EXPIRY:604800}
```

### application.yml vs application-local.yml 역할 분리

| 파일 | 역할 |
|------|------|
| `application.yml` | 모든 환경 공통 기본값. 시크릿은 환경변수 참조 |
| `application-local.yml` | 로컬 개발용 더미값 오버라이드 (git 커밋 가능) |

### 로컬 실행 방법

`application-local.yml`이 로드되려면 **반드시 `local` 프로필을 활성화**해야 한다:

```bash
# Windows
./mvnw.cmd spring-boot:run -Dspring-boot.run.profiles=local

# 또는 환경변수로
set SPRING_PROFILES_ACTIVE=local
./mvnw.cmd spring-boot:run
```

### 결과
- Spring Boot 기동 시 `jwt.*`, `s3.*`, `app.*` 등 모든 속성 정상 해석
- `local` 프로필 활성화 시 `application-local.yml`이 환경변수 없이도 동작
- 프로덕션 환경에서는 환경변수로 모든 값 주입

## [2026-04-16] 어드민 계정 추가

### 메타 정보
- **날짜:** 2026-04-16
- **작업명:** 초기 어드민 로그인 계정 추가 (Flyway 마이그레이션)
- **대상 파일:** `backend/src/main/resources/db/migration/V3__add_admin_user.sql` (신규 생성)

### 프롬프트 (사용자 요청)
```
어드민 로그인 계정 하나 추가해줘
```

### 추가된 계정 정보

| 항목 | 값 |
|------|----|
| 이메일 | `admin@example.com` |
| 비밀번호 | `Admin1234!` |
| 이름 | 관리자 |
| 역할 | `ADMIN` |
| 로그인 방식 | `LOCAL` |

### 수정 내용

**신규 생성: `V3__add_admin_user.sql`**
```sql
INSERT INTO users (email, password, name, role, provider)
VALUES (
    'admin@example.com',
    crypt('Admin1234!', gen_salt('bf', 10)),
    '관리자',
    'ADMIN',
    'LOCAL'
)
ON CONFLICT (email) DO NOTHING;
```

### 기술 결정 사항
- `pgcrypto`의 `crypt('bf', 10)` 사용 → Spring Security `BCryptPasswordEncoder`(`$2a$10$...`) 와 완전 호환
  - V1 마이그레이션에서 이미 `CREATE EXTENSION IF NOT EXISTS "pgcrypto"` 설치됨
- `ON CONFLICT (email) DO NOTHING` 추가 → 멱등성 보장 (재실행 시 중복 오류 없음)

### 적용 방법
Spring Boot 재기동 시 Flyway가 V3를 자동 실행:
```bash
./mvnw.cmd spring-boot:run -Dspring-boot.run.profiles=local
```

## [2026-04-16] Docker backend-1 기동 실패 — `jwt.*` 속성 미해석 (이미지 캐시 문제)

### 메타 정보
- **날짜:** 2026-04-16
- **작업명:** Docker 백엔드 이미지 재빌드 필요 (application.yml 미포함)
- **대상 파일:** 코드 수정 없음 — 재빌드 명령 안내

### 프롬프트 (사용자 요청)
```
backend-1 | Caused by: java.lang.IllegalArgumentException:
  Could not resolve placeholder 'jwt.access-token-expiry' in value "${jwt.access-token-expiry}"
```

### 오류 원인
이전 세션에서 `application.yml`을 신규 생성했으나,
Docker 백엔드 이미지는 **그 이전에 빌드된 캐시된 이미지**를 사용 중이었다.

```
Dockerfile 빌드 흐름:
  COPY src ./src          ← application.yml 포함
  RUN ./mvnw package      ← jar 생성
  → jar 안에 application.yml 없음 (이전 빌드 캐시 사용)
```

`--build` 없이 `docker compose up`을 실행하면 기존 이미지를 재사용하므로
새로 추가된 `application.yml`이 jar에 포함되지 않아 속성 해석 실패.

### 해결 방법
코드 변경 없음 — 이미지 재빌드만 필요:

```bash
docker compose -f docker-compose.yml up --build backend -d
```

### 특이사항
- `--build` 플래그는 소스 변경(Java 코드, 설정 파일) 후 항상 필요
- `src/main/resources/` 파일 변경 시에도 반드시 재빌드해야 jar에 반영됨
- `.env` 파일의 `JWT_SECRET=your-secret-key-minimum-32-characters-long`은 32자 이상으로 유효함

#### 버그 1 (치명적) — Axios 인터셉터 데드락으로 로그인 무한 로딩

**파일:** `frontend/src/lib/axios.ts`

**증상:** 이메일/비밀번호를 입력하고 로그인 버튼을 눌러도 로딩 스피너가 무한히 돌고 에러가 표시되지 않음

**원인:**

```
로그인 POST /api/v1/auth/login → 401 반환
  └─ 인터셉터: isRefreshing=false → isRefreshing=true, 갱신 시도
       └─ 갱신 POST /api/v1/auth/refresh → 401 반환
            └─ 인터셉터: isRefreshing=true → failedQueue에 추가 (대기)
                 ← 갱신 완료를 기다림 (갱신이 큐에서 대기 중) → 데드락
```

`/auth/` 엔드포인트에서 받은 401은 "토큰 만료"가 아닌 "인증 실패"이므로
토큰 갱신을 시도해서는 안 된다.

**수정 내용:**

```diff
+ // 인증 엔드포인트는 즉시 에러 반환 (갱신 시도 불필요)
+ if (originalRequest.url?.includes('/auth/')) {
+   return Promise.reject(error)
+ }
  if (error.response?.status === 401 && !originalRequest._retry) {
```
